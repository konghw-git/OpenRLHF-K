✎ 自测
  1. 为什么 PG 模式下每个 actor 只申请 0.2 GPU？
    参考答案
    让 actor / ref / critic / reward / vLLM 五方共享同一张物理卡，靠 sleep / offload 时分复用；Ray 的资源额度只是调度记账，不是硬隔离。
  2. algo.kl.init_coef=0 时系统少了哪个 actor？为什么可以少？
    参考答案
    ReferenceModelActor。KL 系数为 0 意味着不需要 log πref，冻结参考模型没有任何用途，直接不创建以省显存（train_ppo_ray.py:93-103）。
  3. GRPO 训练时哪两个 actor 不存在？
    参考答案
    Critic（group_norm 是 critic-free 算法）；以及若用 reward_func / remote RM，RewardModelActor 也不部署。若再把 KL 系数设 0，连 Reference 也可以省。

分清三个 log_probs（贯穿全部 loss 代码）

字段含义来源
rollout_log_probs\(\log \pi_{\text{rollout}}\) —— vLLM 生成时的策略（可能已过时）vLLM 生成阶段
action_log_probs\(\log \pi_{\theta}\) —— 训练时 actor 重算的当前策略actor forward
base_action_log_probs\(\log \pi_{\text{ref}}\) —— 参考策略，用于 KLreference actor
⚑ Token-in-token-out

轨迹永远以 token id + logprob 传递，训练与采样之间从不重新 detokenize。这消灭了 chat template 漂移、BOS/EOS 不一致等一整类 silent bug —— 很多自研 RLHF 框架的收敛玄学问题根源就在这。

⚠ action_mask 的偏移

samples_generator.py:267 中 action_mask = action_mask[1:truncate_length] —— 因为 log_prob 对应"预测下一个 token"，掩码相对 sequences 右移一位。读 loss 代码时脑中要有这个对齐关系。

自定义 reward 函数签名（RLVR 最常用）

def reward_func(queries, prompts, labels):
    return {
        "rewards": tensor,   # 进 advantage 计算
        "scores":  tensor,   # 进 dynamic_filtering 判断
        "extra_logs": dict,  # 自定义 wandb 指标
    }
✎ 自测
  1. n_samples_per_prompt=8 且 rollout.batch_size=128，一次 generate_samples 产出多少条序列？哪些算法必须 n>1？
    参考答案
    1024 条。rloo / reinforce_baseline / group_norm / dr_grpo 需要组内 baseline，必须 n>1；dynamic_filtering 同样要求 n>1。
  2. 多轮 agent 里环境反馈的 token 会参与 policy loss 吗？靠什么机制排除？
    参考答案
    不会。action_ranges 只标记模型生成的 token，loss 只在这些位置计算；env feedback token 的 rollout_log_prob 填 0，且不在 action_mask 内。
  3. 动态过滤为什么要求 reward 在生成阶段就可得？
    参考答案
    过滤发生在 samples_generator（生成侧），早于 experience_maker，所以只支持 remote RM / reward_func / agent 这些能即时返回 reward 的路径，不支持本地 RM actor。

六种 advantage estimator（--algo.advantage.estimator）

设同一 prompt 的 \(n\) 条样本 reward 为 \(r_1, \dots, r_n\)，组均值 \(\bar r\)、组标准差 \(\sigma\)：

estimator论文名公式全局归一化需要 critic
gaePPO\(\delta_t = r_t + \gamma V_{t+1} - V_t,\ \ A_t = \delta_t + \gamma\lambda A_{t+1}\)✅ (μ,σ)✅
reinforceREINFORCE++\(A_t = G_t = \sum_k \gamma^k r_{t+k}\)✅❌
rlooRLOO\(A_i = r_i - \frac{\sum_{j\ne i} r_j}{n-1}\)（留一均值）❌❌
reinforce_baselineREINFORCE++-baseline
（RLVR 官方推荐）		\(A_i = r_i - \bar r\)，再全局 \(/\sigma\)✅❌
group_normGRPO\(A_i = \dfrac{r_i - \bar r}{\sigma + 10^{-9}}\)❌（组内已除 σ）❌
dr_grpoDr. GRPO\(A_i = r_i - \bar r\)（去掉 /σ，修正梯度偏差）❌❌
⚑ 记忆锚点

gae 之外全部 critic-free 且 γ 强制 1.0；train_ppo_ray.py:600-601 非 gae 时直接把 critic 路径设 None。--algo.advantage.no_std_norm 可保留减均值但关掉除 σ。

KL 的两种用法（最容易混淆的设计分叉）

algo.kl.use_loss=False（默认，PPO 传统）algo.kl.use_loss=True（GRPO 式）
KL 去哪变成 per-token reward 惩罚：\(r_t \mathrel{+}= -\beta \cdot \mathrm{KL}_t\)作为独立 loss 项加在 policy loss 旁
推荐 estimator只用 k1k2 或 k3（k1 无效）
ref logprobs用完即弃保留传给 actor 训练
典型系数0.01（RLHF 对话）1e-5（RLVR）；GRPO 常配 k3

三种 KL 近似（models/utils.py:64-95，源自 Schulman 博客），记 \(\Delta = \log\pi - \log\pi_{\text{ref}}\)：

k1
$$k_1 = \Delta$$
无偏但可为负
k2
$$k_2 = \tfrac{1}{2}\Delta^2$$
非负，低方差
k3
$$k_3 = e^{-\Delta} - 1 + \Delta$$
非负、无偏，GRPO 论文用的就是它

自适应 KL（kl_controller.py:4-18）：设了 --algo.kl.target 才启用：

$$\beta \leftarrow \beta \cdot \Big(1 + \mathrm{clip}\big(\tfrac{\mathrm{KL}}{\mathrm{target}} - 1,\ -0.2,\ 0.2\big) \cdot \tfrac{n_{\text{steps}}}{\text{horizon}}\Big)$$

长度惩罚（reasoning 训练必调）

DAPO overlong（length_penalty.py:16-58）

设软区间 overlong_buffer_len \(= L_{\text{buf}}\)，超出 \(\text{max\_new\_tokens} - L_{\text{buf}}\) 的部分按比例罚：

$$\text{penalty} = -\frac{\min(\text{len} - (\text{max\_new} - L_{\text{buf}}),\ L_{\text{buf}})}{L_{\text{buf}}} \times \text{factor}$$

惩罚线性增长，最大罚 −factor。

ProRL stop-properly（length_penalty.py:61-106）

对 finish_reason=="length" 的截断样本：系数 ≥0 时 reward 乘系数（0 = 清零）；<0 时直接覆盖为该负值。两者可叠加。

✎ 自测
  1. Dr. GRPO 相对 GRPO 只改了一件事，是什么？为什么这个改动能修正偏差？
    参考答案
    去掉了组内除以 σ。当一组样本几乎全对或全错时 σ 很小，除以 σ 会放大这些"低信息量"组的梯度，产生长度与难度偏差；只减均值保持梯度无偏。
  2. use_kl_loss=True 时 experience_maker.py 为什么跳过 KL 计算但保留 base_action_log_probs？
    参考答案
    KL 不再进 reward，所以经验构造阶段不需要算；但 actor 训练时要在 loss 里现算 KL 项，因此 ref 的 logprobs 必须随 experience 传下去（experience_maker.py:205-219）。
  3. 为什么 rloo / group_norm / dr_grpo 不做全局 advantage 归一化而 reinforce_baseline 做？
    参考答案
    对照 experience_maker.py:315 的白名单（gae / reinforce / reinforce_baseline）。rloo 与 group_norm 的组内变换已经控制了尺度（后者已除 σ）；dr_grpo 有意保持"只减均值"的无偏性；reinforce_baseline 的设计则是"组内减均值 + 全局除 σ"两段式。

PolicyLoss 主干（loss.py:116-231）

记 \(r_t = \exp\big(\mathrm{clamp}(\log\pi_\theta - \log\pi_{\text{old}},\ \pm 20)\big)\)：

标准 PPO clip（ε 默认 0.2，可非对称）
$$L = -\min\Big(r_t A,\ \ \mathrm{clip}(r_t,\ 1-\varepsilon_{\text{low}},\ 1+\varepsilon_{\text{high}})\, A\Big)$$
--actor.eps_clip_low_high 0.2 0.27 即 DAPO 的 clip-higher 技巧：抬高上界鼓励探索。
Dual-clip PPO（--actor.dual_clip c，c > 1，仅 A < 0 时生效）
$$L = -\begin{cases} \max\big(\min(r_tA,\ \text{clip})\,,\ c \cdot A\big) & A < 0 \\[4pt] \min(r_tA,\ \text{clip}) & A \ge 0 \end{cases}$$
给负 advantage 加下界，防止 ratio 过小导致过度惩罚把策略推崩。
GSPO（--actor.policy_loss_type gspo，loss.py:170-178）
$$r_{\text{seq}} = \exp\Big(\frac{1}{|a|}\sum_t \Delta\log p_t\Big)$$
ratio 换成序列级几何平均，且强制 sequence-level 聚合。适合 MoE 等 token ratio 噪声大的场景。

聚合语义（aggregate_loss，loss.py:11-39）—— 本仓库最精细的工程点

token-level（默认）
$$L = \frac{\sum_{i,t} \ell_{i,t}\, m_{i,t}}{N_{\text{tokens}}^{\text{global}}} \times dp$$
分母是全局有效 token 总数 —— 长回答权重大。
sequence-level
$$L = \frac{1}{B_{\text{global}}}\sum_i \Big(\frac{\sum_t \ell_{i,t} m_{i,t}}{\sum_t m_{i,t}}\Big) \times dp$$
先序列内平均、再样本间平均 —— 每条样本等权（GRPO 论文原味）。
⚑ 两个隐藏的正确性保证
  • 乘 \(dp\) 是为了抵消 DeepSpeed 跨 DP rank 的梯度平均，保证梯度与单卡全量 batch 严格等价。
  • loss_utils.py:80-105：梯度累积时把同一 optimizer step 的所有 micro-batch 的 token 数先汇总再分摊，避免"均值的均值"偏差 —— tests/test_loss_aggregation.py 专门验证 token 数不均时两种算法结果不同。

vLLM off-policy 校正（--algo.advantage.is_correction_enable）

rollout 用的 \(\pi_{\text{rollout}}\) 与训练时的 \(\pi_{\text{old}}\) 可能不同（async / partial rollout 下必然不同），用重要性权重修正：

$$w_t = \exp\big(\log\pi_{\text{old}} - \log\pi_{\text{rollout}}\big)$$
type行为场景
tis\(w\) 截断到 [0.5, 5.0] 后乘 loss默认
icepop阈值外的 token 直接置 0（mask 掉）partial rollout 官方推荐
seq-mask-tis序列级几何均值超阈值 → 整句 mask，句内再乘 \(w\)更保守

Critic 侧与 ReplayBuffer

  • ValueLoss（loss.py:234-270）：value clip（默认 0.5）+ 两个 MSE 取 max；--critic.freezing_steps N 让前 N 步只训 critic 不动 actor（PPO 冷启动稳定性技巧）。
  • dynamic batch（replay_buffer.py:91-177）：开 --train.dynamic_batch_enable 后不再按固定 micro_batch_size，而是按 max_tokens_per_gpu 的 token 预算装箱，用 Karmarkar–Karp 算法均衡各 micro-batch 的总长，跨 DP rank 对齐 step 数。变长 reasoning 输出下利用率远高于定长 batch。
✎ 自测
  1. token-level 和 sequence-level 聚合，哪个会让"一条 8000 token 的长回答"对梯度影响更大？GRPO 论文的原始设定是哪个？
    参考答案
    token-level（长序列贡献更多 token 项）。GRPO 原始设定是 sequence-level（每条样本等权）。
  2. dual_clip 只在 advantage 为负时起作用，为什么？
    参考答案
    A ≥ 0 时 min(surr1, surr2) 已有上界（clip 上限封顶）；A < 0 时若 ratio → 0，−min(...) 会无界增大，dual_clip 用 c·A 给它加下界。
  3. async 训练不开 is_correction 会发生什么？
    参考答案
    πrollout 落后 πold 一到多个 batch，重要性比率整体偏移但未被修正，梯度估计有系统性偏差，通常表现为训练不稳或 reward 虚高后崩掉。

Async 的本质

生成和训练变成生产者/消费者，--train.async_queue_size（默认 1）就是最大允许的 off-policy staleness（按 batch 计）。再加 --train.partial_rollout_enable 则权重切换时 vLLM 只 pause/resume，in-flight 序列前半旧权重后半新权重 —— 所以官方要求配 is_correction（icepop）。

维度SyncAsync
流水线串行 generate → train → broadcastgenerate / train 并行
staleness0最多 async_queue_size 个 batch
vLLM sleep支持不支持（互斥）
colocate_all全部模型 + vLLM 共卡仅 DeepSpeed 模型共卡，vLLM 独立 GPU 组

DeepspeedStrategy 要点

  • 梯度累积自动算：\(gas = \dfrac{\text{train.batch\_size} \times ring \times tp}{\text{micro\_batch\_size} \times \text{world\_size}}\)
  • Muon 优化器（--actor.optim muon）：2D 权重走 Muon（lr 0.02）、embedding/head/1D 参数走 aux-Adam；与 adam_offload 不兼容；DS≥0.18.9；用 Muon 时 grad clip 建议设 0 —— DS 的 clip 发生在 Newton–Schulz 之后，会把更新缩小约 700 倍（deepspeed.py:331-344，典型的"读了源码才知道"的坑）。
  • Ring attention：3D mesh (dp, sp, tp)，ring_attn_size>1 强制要求 packing_samples。
  • EMA（--train.enable_ema，β=0.992）：每 step 后在 CPU 上做滑动平均，保存时存 EMA 权重 —— RLHF 出模型更稳的老技巧。
✎ 自测
  1. 为什么 vllm.enable_sleep 和 async_enable 互斥？
    参考答案
    sleep 靠训练/生成严格串行地时分复用同一组 GPU；async 恰恰要二者同时进行，vLLM 永远不能睡。
  2. partial rollout 相比普通 async 多引入了什么噪声？框架用什么补救？
    参考答案
    同一条序列前半由旧权重、后半由新权重生成（token 级混合策略）。补救：ICEPOP 重要性采样校正，把 ratio 异常的 token 直接 mask 掉。
  3. 什么条件下权重同步走 CUDA IPC？为什么该条件下 IPC 更优？
    参考答案
    nccl + colocate_all + 非 async。此时 actor 与 vLLM worker 在同一张物理卡的同一显存里，IPC handle 零拷贝直读，省去一轮网络/NCCL 传输。

一页公式速查

Policy Loss

PPO
$$L = -\mathbb{E}\big[\min(r A,\ \mathrm{clip}(r, 1{-}\varepsilon_l, 1{+}\varepsilon_h) A)\big]$$
\(r = \pi_\theta / \pi_{\text{old}}\)
Dual-clip（A<0 时）
$$L = -\max\big(\min(\text{surr}_1, \text{surr}_2),\ c \cdot A\big)$$
GSPO
$$r_{\text{seq}} = \exp\Big(\tfrac{1}{|a|}\textstyle\sum_t \log r_t\Big)$$
seq-level 聚合强制开启

Advantage Estimators

GAE
$$\delta_t = r_t + \gamma V_{t+1} - V_t,\quad A_t = \delta_t + \gamma\lambda A_{t+1}$$
returns = A + V
REINFORCE++
$$A_t = \sum\nolimits_k \gamma^k r_{t+k}$$
全局 (μ,σ) 归一化
RLOO
$$A_i = r_i - \frac{\sum_{j \neq i} r_j}{n-1}$$
R++-baseline
$$A_i = r_i - \bar r_{\text{group}}$$
再全局 /σ
GRPO
$$A_i = \frac{r_i - \bar r}{\sigma_{\text{group}} + 10^{-9}}$$
Dr. GRPO
$$A_i = r_i - \bar r$$
无任何 σ 归一化

KL 与 reward 合成

KL 估计器（Δ = logπ − logπ_ref，clamp ±10）
$$k_1 = \Delta \qquad k_2 = \tfrac{1}{2}\Delta^2 \qquad k_3 = e^{-\Delta} - 1 + \Delta$$
reward 合成（use_kl_loss=False）
$$r_t = -\beta\,\mathrm{KL}_t + \mathbb{1}[t = \text{EOS}] \cdot \mathrm{clip}(r, -10, 10)$$

其它

DAPO overlong penalty
$$p = -\frac{\min\big(\text{len} - (\text{max} - L_{\text{buf}}),\ L_{\text{buf}}\big)}{L_{\text{buf}}} \cdot f$$
token-level 聚合
$$L = \frac{\sum \ell \cdot m}{N_{\text{tokens}}^{\text{global}}} \times dp$$
seq-level 聚合
$$L = \frac{1}{B}\sum_i \overline{\ell_i} \times dp$$
IS 校正
$$w = e^{\log\pi_{\text{old}} - \log\pi_{\text{rollout}}}$$
tis = clamp(w)；icepop = mask(w ∉ [lo, hi])
